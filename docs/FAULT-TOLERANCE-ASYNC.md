# 异步位置写入：重复实验结果

分支：`perf/async-positions`（已合并 master `51947c4`）
基线：`68b0f46`

## 结论先说

**异步写入确实能大幅改善 MySQL 慢查询场景，但没有改善冷启动和重连错误率。**

之前单次实验里“冷启动 8.02% → 6.70%、重连 6.86% → 6.72%”的差异，在重复实验后不成立，属于实验波动。

## 实验方法

- 同一台 Windows 机器；
- 临时 MySQL 8.0.33 + 临时 Redis 8.10.3；
- 4 个压测 shard；
- 每个模式重复 3 次；
- 同步/异步使用同一个 master 代码，仅切换 `CAMPUS_POSITION_WRITE_BEHIND=0/1`。

## 重复实验结果

### 冷启动 / Redis / 重连（3 次均值）

| 场景 | 同步均值 | 异步均值 | 判断 |
|---|---:|---:|---|
| cold-2000 错误率 | 6.81% | 6.86% | 无改善 |
| cold-2000 P95 | 1520ms | 1506ms | 基本持平 |
| reconnect-storm 错误率 | 17.6%（含一次 39.1% 异常） | 6.71% | 中位数都约 6.75%，无显著改善 |
| reconnect-storm P95 | 1676ms | 1498ms | 略好但不足以定性 |
| redis-outage 错误率 | 0% | 0% | 持平 |
| redis-recovery 错误率 | 0% | 1.22%（含一次异常） | 无改善 |

重连的同步均值被一次 39.1% 的异常拉高；按中位数看，同步和异步都在 6.75% 左右。**不能说异步修复了重连。**

### MySQL 慢查询（3 次均值）

| 指标 | 同步均值 | 异步均值 |
|---|---:|---:|
| 写入错误率 | **26.99%** | **0.05%** |
| 成功写入 | 13,208 / 18,090 | 18,081 / 18,090 |
| P95 | 1722ms | 3145ms |
| P99 | ~4258ms | ~4768ms |

这是稳定的结论：

- 同步写入在 MySQL 锁表期间大量失败；
- 异步队列吸收写入，恢复后 drain，成功率接近 100%；
- 代价是故障期间 P95 延迟升高，因为请求在等队列消化。

## 为什么之前看起来“变快、准确率升高”

- 单次实验的冷启动/重连波动很大；
- 重连同步有一次异常到 39.1%，拉高均值；
- 慢查询的改善是真实的，但延迟代价也被掩盖在单次结果里；
- 因此不能只看一次运行的“错误率下降”，需要重复取中位数/均值。

## 结论

保留异步写入，但只把它定位为 **MySQL 故障隔离**，不宣称它修复冷启动/重连。

回滚开关：

```text
CAMPUS_POSITION_WRITE_BEHIND=0
```
