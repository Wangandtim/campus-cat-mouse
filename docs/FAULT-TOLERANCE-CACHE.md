# 玩家状态缓存 TTL 实验

分支：`perf/cache-ttl`

## 改动

```text
player-cache TTL: 12s → 30s
```

不变：

- 角色/共享/场次变化仍通过 `profileChanged` 失效缓存；
- 握手仍强制刷新数据库，不绕过安全复核；
- 位置异步写入保持不变。

## MySQL 慢查询重复实验

3 次 `--mysql-fault-only`，异步写入开启。

| 指标 | TTL 12s 基线 | TTL 30s |
|---|---:|---:|
| 错误率 | 0.05% | 0.00% |
| 成功写入 | 18,081 / 18,090 | 18,090 / 18,090 |
| P95 均值 | 3145ms | 约 2512ms |
| P99 均值 | 约 4768ms | 约 4549ms |

原始数据：

- `cache-ttl-1.json`
- `cache-ttl-2.json`
- `cache-ttl-3.json`
- 基线：`mysql-repeat-1-*.json`

## 重连

3 次 reconnect-storm：

- TTL30：6.85 / 6.82 / 7.09，均值约 6.92%；
- TTL12：6.85 / 6.63 / 6.85，均值约 6.78%。

差异在实验波动范围内，**不能宣称改善重连**。

## 结论

- TTL 30s 在 MySQL 慢查询下稳定降低 P95，且不增加写入错误；
- 重连没有改善；
- 缓存失效路径不变，安全测试通过；
- 可以保留 TTL 30s，但只能作为慢查询降延迟优化，不解决 cold/reconnect。
