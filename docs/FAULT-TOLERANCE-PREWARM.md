# 握手预热门控实验

分支：`perf/session-version`（未合并）

## 假设

- 启动时预热玩家状态缓存；
- 初始握手先读缓存，不再每个连接查 MySQL；
- recovered 重连仍强制刷新数据库，保留安全复核。

## 实现

- `warmPlayers(ids)` 批量预热玩家状态；
- target 启动后预热 2000 名玩家；
- 初始握手使用缓存；
- recovered 连接保留 `revalidate` 数据库刷新。

安全测试通过：

```text
revalidates each recovered player ... pass
```

## 3 次重复结果

### cold-2000

| 次数 | 错误率 |
|---|---:|
| 1 | 6.17% |
| 2 | 7.36% |
| 3 | 7.40% |
| 均值 | **6.98%** |

当前异步基线均值：约 6.86%。  
预热后没有改善，反而略差。

### reconnect-storm

| 次数 | 错误率 |
|---|---:|
| 1 | 6.99% |
| 2 | 7.27% |
| 3 | 7.32% |
| 均值 | **7.19%** |

当前异步基线均值：约 6.71%。  
没有改善。

## 结论

**不合并。**

- 预热缓存没有降低 cold/reconnect 错误率，反而略差；
- cold 阶段的主要错误发生在客户端/负载生成器连接调度，不是服务端玩家状态查询；
- reconnect 阶段错误也不是玩家状态缓存缺失；
- 继续在服务端加缓存不会解决这两个场景。
