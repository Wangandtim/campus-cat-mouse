# 容错优化方案

基于 2026-11-24 本机全量压测结果：[REPORT-2026-11-24.md](../tests/load/REPORT-2026-11-24.md)。

| 场景 | 当前错误率 | 目标 |
|---|---:|---:|
| steady-2000/2010 | 0% | 保持 0% |
| cold-2000 | 8.02% | <1% |
| reconnect-storm | 6.86% | <1% |
| mysql-slow-query-pool-full | 24.04% | 快速失败，<1% |

## 1. 接入与冷启动

- 握手令牌桶 + 有界等待队列；
- 超限返回 `503` 和 `Retry-After`，不直接打穿数据库；
- 客户端指数退避 + 抖动；
- 活动开始前预热连接池与进程；
- LB 就绪检查通过后再接入。

## 2. MySQL 背压

- 位置写入 / 状态校验 / 榜单读取分 lane；
- 池排队超时快速失败，避免一个慢查询拖死全部请求；
- 位置写入优先级高于 1 秒快照；
- 角色和共享状态使用缓存，减少每轮数据库校验；
- 批量 upsert、合并位置写入；
- 针对慢查询补索引并设置 query timeout；
- 超过连接池阈值时熔断非关键读取。

## 3. 重连风暴

- 客户端随机抖动，禁止同秒集中重连；
- 重连单独限流，不与正常位置写入抢连接；
- 使用 Socket.IO connectionStateRecovery；
- 重连只补最新位置，不重放历史；
- 多实例通过 Redis adapter 和粘性会话分摊；
- 负载均衡使用最少连接策略。

## 4. 客户端离线缓冲

- 位置样本本地队列；
- `sampleId` 幂等；
- 网络恢复后只补最新一条；
- 服务端 `retryAfter` 只触发一次重试。

## 5. 验收

```text
steady-2000/2010 写入错误 0%
cold-2000 < 1%
reconnect-storm < 1%
mysql-slow-query < 1%
可见位置 P95 < 2 秒
```

## 实施顺序

1. 客户端退避与离线缓冲；
2. 握手准入与快照降级；
3. MySQL lane、超时和熔断；
4. 多实例 Redis/HA；
5. 在目标生产链路重新压测。

在未完成回归测试前，不建议直接改连接池、事务或实时广播主路径，避免影响现有功能。
